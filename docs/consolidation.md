## 整合时记录的问题（已于 2026-10-16 修复）

以下为 2026-10-12 整合时的发现，原始症状保留供追踪：

1. 本地新上传的 `videos.duration` 初始为空，Worker 在进入 FFprobe 前调用 `getSourceInfo()` 并要求时长非空，导致新上传任务失败。
2. 隐私笔记在任务完成前使用空到期时间写入，正式迁移 `0008` 的 `ephemeral_ai_notes.expires_at` 却要求非空；对应测试表允许为空。
3. API 提交数据库任务后才向 Redis 入队；队列失败会留下 `queued` 记录，重试请求不会重新入队。
4. SSE 订阅已有实现，但生产流程未调用进度发布，当前进度更新依靠前端轮询。

2026-10-16 修复：上传源先下载和 FFprobe，再以真实时长准入和计费；新增只追加的 `0010` 迁移，允许未完成隐私笔记暂不设置到期时间，完成时统一写入 24 小时到期；重试会重新补发 queued 任务，API 每 10 秒扫描持久化 queued 任务并使用稳定 jobId 补发；SSE 从数据库读取独立 Worker 写入的进度，在连接关闭时释放订阅并发送保活。

同时修正本地 dev 的 Worker 入口、根目录环境加载、TS 自动编译、Vite API 代理、宿主数据库迁移路径、登录后积分/历史加载、分析启动错误传递以及 SSE 完成回调循环。提供无需 Docker 的 `local:dev` 与 [验证说明](local-development.md)。

已进行真实 PostgreSQL/FFmpeg 的标准、隐私模式集成测试，及 HTTP 注册/登录/上传/播放/删除与浏览器 SSE/取消验证。集成测试的 AI 响应是 fixture；真实 Groq/LLM 与公开平台链接仍需有效配置后验收，不能据此声称外部 Provider 已验证。
