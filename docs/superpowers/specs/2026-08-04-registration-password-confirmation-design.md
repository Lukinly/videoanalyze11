# 注册密码二次确认设计

## 目标

在注册流程中增加确认密码机制，避免用户因输入错误密码而创建无法登录的账号。校验必须同时存在于浏览器和 API，确认密码只用于本次请求，不写入数据库。

## 范围

本次只调整注册流程，不改变数据库表结构、登录流程、密码哈希算法或邮箱验证流程。

## 设计

### 前端

`RegisterPage` 增加 `confirmPassword` 状态和密码确认输入框。确认密码输入框使用密码类型和 `new-password` 自动填充提示。

提交表单时先比较 `password` 与 `confirmPassword`：

- 不一致时显示中文错误提示，不发起 API 请求；
- 一致时按现有流程调用注册 API；
- 成功和失败状态、忙碌状态保持现有行为。

客户端 API 类型将注册请求扩展为 `{ email, password, confirmPassword }`。

### API

注册接口和 `AuthServiceContract` 接收 `confirmPassword`。认证服务在邮箱校验和密码长度校验后、创建用户前比较两个密码。

不一致时返回 `DomainError`：

- code: `PASSWORD_MISMATCH`
- HTTP status: `400`
- message: `passwords do not match`

失败路径不能创建用户、生成密码哈希、生成邮箱验证记录或发送验证邮件。成功路径保持现有行为。

### 数据安全

- 数据库仍只保存 bcrypt 密码哈希；
- `confirmPassword` 不进入 repository，不进入数据库；
- API 不返回任一密码字段。

## 测试策略

采用测试驱动开发：

1. API 认证服务测试先证明密码不一致时注册失败，且用户仓储和邮件发送器不会被调用。
2. API 路由测试验证 `confirmPassword` 会传递给认证服务，且原有成功响应不包含密码或令牌。
3. 注册页面测试验证确认密码字段存在，不一致时显示错误并阻止请求，一致时提交完整注册数据。
4. 运行相关测试后运行完整测试套件，确认现有注册、登录、邮箱验证行为没有回归。

## 验收标准

- 注册页面可输入密码和确认密码；
- 两次密码不一致时，页面立即阻止注册并给出明确提示；
- 直接调用 API 绕过前端时，后端仍拒绝不一致密码；
- 不一致请求不会产生用户或验证邮件记录；
- 一致密码可以继续现有邮箱验证流程；
- 所有相关测试和全量测试通过。
